# Сервер уведомлений и автосинхронизации

Необязательный компонент трекера. Принимает вебхуки Monobank, накапливает операции для
приложения и отправляет push-уведомления на iPhone. Node.js в Docker, единственная
зависимость — `web-push`.

Без него трекер работает полностью: операции загружаются вручную через импорт выписки.

## Что он даёт

- Операция приходит на сервер в момент оплаты — приложение забирает её при открытии,
  без лимитов Monobank на запросы и без выбора периода вручную.
- Push-уведомления: новые траты, поступления, переводы, напоминания о подписках
  и рассрочках. Каждый вид включается отдельно, есть порог суммы.

Токен Monobank на сервер не попадает: адрес вебхука регистрирует само приложение
запросом с телефона. Сервер хранит только операции по карте и подписки на уведомления.

## Требования

- сервер с Docker и Docker Compose;
- домен, направленный на этот сервер — Monobank принимает вебхук только по публичному
  HTTPS-адресу;
- reverse proxy с TLS. Ниже пример на [Caddy](https://caddyserver.com), который получает
  сертификаты автоматически.

## Установка

### 1. Код на сервер

```bash
git clone <адрес вашего репозитория> tracker
cd tracker/server
```

### 2. Секреты

Node на хосте не нужен, всё считает образ из Docker:

```bash
docker run --rm -v "$PWD":/app -w /app node:22-alpine node src/vapid.js --secrets
docker run --rm -v "$PWD":/app -w /app node:22-alpine node src/vapid.js
```

Первая команда выдаёт `DEVICE_TOKEN` и `WEBHOOK_SECRET`, вторая — пару ключей Web Push.

### 3. Настройки

```bash
cp .env.example .env
```

Заполните `.env` значениями из предыдущего шага. Файл в git не попадает.

| Переменная | Назначение |
|---|---|
| `PUBLIC_URL` | публичный адрес сервиса, тот же, что в reverse proxy |
| `DEVICE_TOKEN` | вводится в приложении один раз, открывает доступ к API |
| `WEBHOOK_SECRET` | случайная часть адреса вебхука |
| `VAPID_PUBLIC`, `VAPID_PRIVATE` | ключи подписи push-уведомлений |
| `VAPID_SUBJECT` | контакт для push-сервисов, например `mailto:you@example.com` |
| `ALLOWED_ORIGINS` | адрес, откуда открывается приложение, например `https://<логин>.github.io` |
| `PORT` | порт внутри контейнера, по умолчанию 8090 |

### 4. Запуск

```bash
docker compose up -d --build
docker compose logs -f
```

В логе должно быть «трекер-сервис слушает», «push настроен» и «каталог данных
/data: доступен для записи».

Контейнер слушает только `127.0.0.1:8090`, работает от непривилегированного пользователя,
с read-only файловой системой и лимитом памяти. Данные лежат в именованном томе `tracker-data`.

### 5. Reverse proxy

Пример блока для Caddy — добавляется к уже работающей конфигурации, не затрагивая
остальные сайты:

```caddyfile
tracker.example.com {
    reverse_proxy 127.0.0.1:8090
}
```

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
curl -s https://tracker.example.com/health   # {"ok":true}
```

### 6. Настройка приложения

В трекере: **Ещё → Сервер и уведомления**

1. Адрес сервера и `DEVICE_TOKEN` → «Подключить».
2. «Включить автосинхронизацию Monobank» — приложение зарегистрирует адрес вебхука
   в банке. Monobank должен быть подключён в блоке выше.
3. «Включить уведомления на этом айфоне» → разрешить в системном запросе.

Уведомления работают на iOS 16.4 и новее и только в приложении, добавленном
на экран «Домой».

## Обслуживание

```bash
# обновление
git pull && docker compose up -d --build

# резервная копия данных сервера
docker compose exec tracker-notify cat /data/data.json > backup.json

# состояние: адрес вебхука, число подписок, время последней операции от банка
curl -s -H "X-Device-Token: <токен>" https://tracker.example.com/api/state
```

Если сервис был недоступен дольше нескольких минут, Monobank отключает вебхук после
трёх неудачных доставок — нажмите «Включить автосинхронизацию Monobank» в приложении
ещё раз. В самом приложении есть кнопка «Проверить связь», которая показывает,
что именно не работает.

## API

| Маршрут | Назначение |
|---|---|
| `GET /health` | проверка живости |
| `GET, POST /hook/<секрет>` | приём операций от Monobank |
| `GET /api/state` | состояние сервиса |
| `GET /api/ops?since=<курсор>` | новые операции для приложения |
| `PUT /api/settings` | какие уведомления слать |
| `PUT /api/reminders` | расписание напоминаний о платежах |
| `POST /api/push/subscribe`, `/unsubscribe` | подписка устройства на push |

Всё, кроме `/health` и вебхука, требует заголовок `X-Device-Token`.

## Устройство

| Файл | Назначение |
|---|---|
| `src/index.js` | HTTP-маршруты |
| `src/store.js` | хранилище: один JSON-файл с атомарной записью |
| `src/notify.js` | текст уведомлений и правила отправки |
| `src/push.js` | отправка Web Push |
| `src/vapid.js` | генерация ключей и секретов |

Тесты: `npm test` — проверки хранилища, дедупликации операций, напоминаний
и формирования уведомлений.

## Безопасность

- Токен Monobank остаётся на телефоне.
- Запросы приложения требуют `DEVICE_TOKEN`, сравнение постоянное по времени.
- Адрес вебхука содержит случайный секрет, есть ограничение частоты запросов.
- CORS открыт только для адресов из `ALLOWED_ORIGINS`.
- Сервис хранит последние 5000 операций; подписки, долги и категории живут
  только на телефоне.
