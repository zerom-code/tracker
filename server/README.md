# Сервер уведомлений и автосинхронизации

Маленький сервис, который принимает вебхуки Monobank, складывает операции для
трекера и шлёт push-уведомления на айфон. Работает в Docker, наружу выставляется
уже установленным на сервере Caddy.

Что он знает: только операции по карте (сумма, описание, MCC, баланс) и подписки
на уведомления. Токен Monobank остаётся на телефоне — вебхук регистрирует само
приложение, напрямую с устройства.

## Развёртывание

Ниже команды под конфигурацию, где Caddy уже работает в systemd и занимает 80/443
(как на сервере с `oblik-bot`). Сервис займёт свободный порт 8090 на localhost —
существующие проекты не затрагиваются.

### 1. Забрать код на сервер

```bash
git clone https://github.com/zerom-code/tracker.git
cd tracker/server
```

### 2. Сгенерировать секреты

Node на хосте не нужен — используем образ из Docker:

```bash
docker run --rm -v "$PWD":/app -w /app node:22-alpine node src/vapid.js --secrets
docker run --rm -v "$PWD":/app -w /app node:22-alpine node src/vapid.js
```

Первая команда выдаст `DEVICE_TOKEN` и `WEBHOOK_SECRET`, вторая — `VAPID_PUBLIC`
и `VAPID_PRIVATE`.

### 3. Заполнить .env

```bash
cp .env.example .env
nano .env
```

```ini
PUBLIC_URL=https://tracker.5-75-224-2.sslip.io
DEVICE_TOKEN=<из шага 2>
WEBHOOK_SECRET=<из шага 2>
VAPID_PUBLIC=<из шага 2>
VAPID_PRIVATE=<из шага 2>
VAPID_SUBJECT=mailto:ваша@почта
ALLOWED_ORIGINS=https://zerom-code.github.io
```

`.env` в git не попадает — он в `.gitignore`.

### 4. Запустить контейнер

```bash
docker compose up -d --build
docker compose logs -f          # должно быть «трекер-сервис слушает» и «push настроен»
curl -s http://127.0.0.1:8090/health   # {"ok":true}
```

В логах старта проверьте последнюю строку — `каталог данных /data: доступен
для записи`. Если там `ТОЛЬКО ЧТЕНИЕ`, чтение будет работать, а запись
(настройки, напоминания) — падать с ошибкой; см. раздел «Диагностика».

Контейнер слушает только `127.0.0.1:8090`, работает от непривилегированного
пользователя, с read-only файловой системой и лимитом памяти 256 МБ. Данные
лежат в именованном томе `tracker-data` — так у контейнера гарантированно есть
права на запись (каталог, смонтированный с хоста, docker создаёт от root).

### 5. Добавить домен в Caddy

Поддомены `sslip.io` резолвятся автоматически, DNS настраивать не нужно —
`tracker.5-75-224-2.sslip.io` уже указывает на 5.75.224.2. Допишите в
`/etc/caddy/Caddyfile` **отдельным блоком**, не трогая существующие:

```caddyfile
tracker.5-75-224-2.sslip.io {
    reverse_proxy 127.0.0.1:8090
}
```

```bash
sudo caddy validate --config /etc/caddy/Caddyfile   # проверить синтаксис
sudo systemctl reload caddy                          # без простоя других сайтов
curl -s https://tracker.5-75-224-2.sslip.io/health    # {"ok":true}
```

Сертификат Caddy выпустит сам при первом обращении.

### 6. Настроить приложение

На айфоне, в трекере: **Ещё → Сервер и уведомления**

1. Адрес сервера: `https://tracker.5-75-224-2.sslip.io`, токен устройства:
   `DEVICE_TOKEN` из `.env` → **Подключить**.
2. **Включить автосинхронизацию Monobank** — приложение зарегистрирует адрес
   вебхука в банке (нужен уже подключённый Monobank в блоке выше).
3. **Включить уведомления** → iOS спросит разрешение.
4. **Отправить тестовое уведомление** — должно прийти на экран блокировки.

Уведомления приходят только в приложение, добавленное на экран «Домой»
(требование iOS 16.4+).

## Обновление

```bash
cd tracker && git pull && cd server
docker compose up -d --build
```

## Резервная копия данных сервера

Основные данные трекера живут на телефоне, на сервере — только очередь операций
и настройки уведомлений. Если нужно скопировать:

```bash
docker compose exec tracker-notify cat /data/data.json > tracker-server-backup.json
```

## Диагностика

```bash
docker compose logs --tail 50          # приём вебхуков и отправка пушей
curl -s -H "X-Device-Token: <токен>" https://tracker.5-75-224-2.sslip.io/api/state | jq
```

В ответе `/api/state` видно: адрес вебхука, число подписок на уведомления,
курсор операций, время последнего вебхука и последнюю ошибку отправки.

Проверить, что банк достучится до вебхука:

```bash
curl -i https://tracker.5-75-224-2.sslip.io/hook/<WEBHOOK_SECRET>   # 200 ok
```

**Ошибка 500 в приложении, а `/health` отвечает.** Значит чтение работает,
а запись — нет: контейнеру не хватает прав на каталог данных. В логах будет
`EACCES: permission denied, open '/data/data.json.tmp'`, а при старте —
`каталог данных /data: ТОЛЬКО ЧТЕНИЕ`. Так бывает, если в `docker-compose.yml`
данные смонтированы с хоста (`./data:/data`): docker создаёт такой каталог от
root, а сервис работает от пользователя `node`. Лечится переходом на именованный
том (уже в текущем `docker-compose.yml`):

```bash
git pull && docker compose down && docker compose up -d --build
```

Либо, если хотите оставить каталог на хосте: `sudo chown -R 1000:1000 data`.

**Если операции перестали приходить.** Monobank повторяет доставку через 60 и
600 секунд, а после третьей неудачи отключает вебхук. Если сервис лежал дольше —
нажмите «Включить автосинхронизацию Monobank» в приложении ещё раз. Ручной импорт
за нужный период при этом никуда не делся.

## Что внутри

| Файл | Назначение |
|---|---|
| `src/index.js` | HTTP-маршруты: вебхук, выдача операций, настройки, push |
| `src/store.js` | Хранилище: один JSON-файл с атомарной записью |
| `src/notify.js` | Текст уведомлений и правила «слать или не слать» |
| `src/push.js` | Отправка Web Push (единственная зависимость — `web-push`) |
| `src/vapid.js` | Генерация ключей и секретов |

Тесты (нужен Node ≥ 20 на машине): `npm test` — 12 проверок хранилища,
дедупликации, напоминаний и формирования уведомлений.

## Приватность и безопасность

- Токен Monobank на сервер не попадает: вебхук регистрирует телефон.
- Все запросы приложения требуют `DEVICE_TOKEN`, сравнение постоянное по времени.
- Адрес вебхука содержит случайный секрет, ограничение частоты — 120 запросов
  в минуту с адреса.
- CORS открыт только для адреса приложения из `ALLOWED_ORIGINS`.
- Сервис хранит последние 5000 операций и не хранит ничего из остального
  трекера — подписки, долги и категории живут только на телефоне.
